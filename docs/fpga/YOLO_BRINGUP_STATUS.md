# YOLO 板级启动状态

截点：2026-11-04。结论以源码、收据和原始日志为准，仿真、时序与板上结果分开记录。

## 当前状态

完整 YOLO 尚未在板上跑通。启动诊断已从“没有启动日志”推进到捕获真实的首次取指访问错误：
`PC=0x00004000`、`cause=1`（同步取指访问错误）、`TVAL=0x00004000`。该地址位于 16 KiB
启动 ROM 之后，说明启动流程没有正常跳入 ITCM。READY 广播、模型上传、整网推理与实测 FPS
均无成功结果。

## 板级证据

启动观察器由独立 Core 时钟域计数、由应用 UART 以外的发送通路输出，只观察事件，
不改变 ROM、ITCM、执行控制、PLL 或时钟约束。

| 项 | 观察结果 |
|---|---|
| LED | LED0 表示 `ddr_init_done && !soc_rst`；LED1/2/3 表示三个时钟域有活动；LED4/7 表示标量提交与提交异常；LED5/6 未观察到 ITCM 范围提交 |
| 串口 | 首次异常前无应用输出；异常后接管 UART TX |
| 异常快照 | `PC=00004000 CAUSE=00000001 TVAL=00004000 INST=00000000` |

`INST=0` 是取指失败事件，表示该次访问没有成功取回指令，不能据此判定为非法指令。

## 根因与修复

定位结论：PDS 综合把译码前端的窄计数比较
`int'(fetch_pop_count) > lane`（无符号窄计数与有符号 `int` 的比较）误判为常量，
在所有综合网表中移除了第二发射槽的有效位寄存器 `decode_q[315]`。表现为取指正常、
分配/发射/完成各 1 次，但退休为 0、最大 ROB 占用为 1，PC 停在启动 ROM。

修复内容：

- 译码入口按 lane 显式比较：`lane == 0 ? fetch_pop_count != 0 : fetch_pop_count == 2`。
- 同类窄无符号比较改为同宽表达，覆盖发射队列、记分板队列、分裂记分板队列、
  取指队列、预测更新队列、返回地址栈与 Flash 读取器。
- 退休训练容量比较改为同宽无符号。
- 启动观测端口在 FPGA 顶层完整连接，避免未连接输入被综合为常量。

修复后该触发器不再被移除；综合 LUT 由 70,331 增加到 79,597，第二发射通道、
第二完成队列与第二分支单元重新成为有效逻辑。板级上位机脚本、UART 协议和固件未改变。

## 观测帧

每轮启动输出 15 行、每行 46 字节的 ASCII 帧：

| 行 | 内容 |
|---|---|
| F0–F3 | 最早四次取指请求地址 |
| B0–B3 | 最早四次退休的 PC、下一条 PC、指令与异常标志 |
| S0–S5 | 分配/发射/完成/退休/重定向计数、ROB 占用、队头与流水状态、首个取指应答 |
| XE | 首个异常记录 |

串口为 115200 8N1，帧可被上位机脚本直接解析；固件运行时按实际外设时钟计算分频。
